# Финал 22.11: final-набор вашего кейса

Для команд-финалистов. Время московское. Всё ниже действует **с момента, когда организаторы сообщат, что доступ включён**.

## Коротко

- Final-набор своего кейса вы берёте через то же API хакатона **тем же командным токеном**, что на разработке. Новых ключей нет.
- Код final-набора вашего кейса организаторы пришлют вашей команде отдельно. Без токена команды-финалиста этого кейса код
  ничего не открывает.
- Разработка — **до 22.11, 11:00**. Автоматических прогонов финала не будет: на финале жюри работает с вашим приложением,
  а приложение берёт данные через `getData`.
- API отдаёт final-набор **до 22.11, 23:59** (токен команды действует до 23.11, 00:00).

## Адрес и токен — как раньше

- Адрес API: `https://hack-api.be-healthy.tech` (на стенде — `HACK_API_URL`), документация — `/docs/`.
- Токен: на стенде `HACK_TEAM_TOKEN`, на ноутбуке — файл `api.token` из вашего набора. Заголовок `Authorization: Bearer <TOKEN>`.
- dev работает по-прежнему, со своим dev-кодом.

## Данные final-набора (все кейсы)

```bash
API=https://hack-api.be-healthy.tech
curl -H "Authorization: Bearer <TOKEN>" "$API/case/<N>/getData?dataset_code=<FINAL_CODE>"
```

`<N>` — номер вашего кейса. Ответ: `{"dataset": {...}, "reference": null}` — эталона в финале нет.

## Кейс 2: final-прогон и /room

`/room` работает только внутри прогона. Final-прогон создаёте сами, командным токеном:

```bash
curl -X POST -H "Authorization: Bearer <TOKEN>" -H "Content-Type: application/json" \
  -d '{"case": 2, "stage": "final"}' "$API/runs"
```

Ответ `201`: `run_id` и `run_token`. **`run_token` выдаётся один раз — сохраните его** (не в репозиторий и не во фронтенд).
Без `"stage"` создаётся dev-прогон, как раньше.

Дальше — как на dev, любым из двух способов:

```bash
# 1) токеном прогона: run_id подставится сам, getData отдаёт final-набор без dataset_code
curl -H "Authorization: Bearer <RUN_TOKEN>" "$API/case/2/getData"
curl -X POST -H "Authorization: Bearer <RUN_TOKEN>" -H "Content-Type: application/json" \
  -d '{"record_id": "<RECORD_ID>"}' "$API/room/session"

# 2) командным токеном + run_id своего final-прогона
curl -H "Authorization: Bearer <TOKEN>" "$API/room/devices?run_id=<RUN_ID>"
curl -X POST -H "Authorization: Bearer <TOKEN>" -H "Content-Type: application/json" \
  -d '{"record_id": "<RECORD_ID>", "run_id": "<RUN_ID>"}' "$API/room/session"
```

- `scenario`, `action`, `state`, `log` — по `session_id`, как на dev.
- **В final нет просьб (`requests` пустой)**: сеанс создаётся только для заезда — `record_id` из `dataset.stays[0]`
  (`kind: "stay"`). Живые просьбы жюри отправляйте как `action` в этот сеанс заезда.
- Время в `/room` виртуальное: `at` у `action` и шагов `scenario` — момент **внутри заезда** (от `check_in_at` до
  `target_wake_at` из набора), а не текущее время 22.11; у `action` `at` можно не указывать. Время вне заезда — `400`.
- Лимита попыток нет: каждый `POST /runs` создаёт **новый** прогон со своим `run_token` и своими комнатами; состояние
  прежнего прогона не переносится. Потеряли `run_token` — создайте новый прогон или работайте способом 2.
- Final-прогон действует до 22.11, 23:59. Таймера 45 минут нет, сдавать ответы через `/run` не нужно.

## Чего в финале нет

- `validate`, `medcheck`, оценки и разбора (`/runs/{id}/evaluation`) — они только на dev.
- Записи результата (`/runs/{id}/result`) — её делает только стенд, для final её нет.
- Автоматической оценки ответов на final-наборе.

## Если ошибка

| Ответ | Что значит |
|---|---|
| `401 UNAUTHORIZED` | неверный или истёкший токен: проверьте, что токен передан целиком после `Bearer ` |
| `403 FORBIDDEN` | не тот код: чужой кейс, чужой final-набор или опечатка в коде |
| `404 NOT_FOUND` | номер кейса в адресе не совпадает с кейсом набора |
| `409 DATASET_CONTEXT` | у токена нет final-набора этого кейса (например, `POST /runs` не для своего кейса) |
| `400 BAD_REQUEST` | командным токеном вызван `getData` без `dataset_code` |

## Куда писать

Организаторам — если после их сообщения о доступе final-набор не открывается или код потерялся. Укажите команду, кейс, метод,
HTTP-статус и `request_id` из ответа. Токены и `run_token` в сообщения не вставляйте.
