## Как подключить деплой

1. Положите `deploy.yml` в репозиторий как `.github/workflows/deploy.yml`.
2. В репозитории на GitHub откройте Settings → Secrets and variables → Actions → New repository secret.
   Имя секрета `STAND_SSH_KEY`, значение — всё содержимое файла `id_ed25519` вместе со строками
   `-----BEGIN ...` и `-----END ...`. Другие секреты не нужны.
3. Сделайте push в `main` (или запустите workflow вручную во вкладке Actions). В логе Actions будет
   вывод сборки, ошибки pip видны там же. В конце `OK: sha=...` — всё работает. Ошибка — шаг станет
   красным, причина будет в выводе.

Для начала можно задеплоить `sample-app`: скопируйте его файлы в корень репозитория.

## Что проверяет стенд после деплоя

1. Собирает образ из вашего кода, останавливает прежний контейнер (не удаляет) и запускает новый.
   На время запуска ваш бэкенд недоступен.
2. Каждые 2 секунды, всего до 60 секунд, отправляет `GET /` на ваш порт `PORT` внутри стенда
   (без HTTPS, ждёт ответа до 2 секунд).
3. **Успех** — любой HTTP-ответ, даже 404 или 500: стенду важно, что сервер слушает порт и отвечает по HTTP.
   Тогда новая версия остаётся, а в Actions появляется `OK: sha=...`.
4. **Неудача** — за 60 секунд не было ни одного ответа, или контейнер упал либо перезапустился.
   Тогда стенд покажет последние 50 строк логов новой версии и вернёт прошлую.

Советы:

- держите `GET /health` с ответом 200 и `{"status": "ok"}`: по нему удобно проверять себя;
- запускайте сервер сразу, а долгую подготовку (загрузку данных, прогрев) делайте после старта
  или по первому запросу: иначе можно не уложиться в 60 секунд.

## API хакатона

| Что | Значение |
|---|---|
| Адрес | `https://hack-api.be-healthy.tech` |
| Документация | https://hack-api.be-healthy.tech/docs/ (открывается без токена), схема — `https://hack-api.be-healthy.tech/openapi.json` |
| Авторизация | заголовок `Authorization: Bearer <токен>` |
| Токен | на стенде — переменная `HACK_TEAM_TOKEN` в env контейнера; на ноутбуке — файл `api.token` из набора |
| Срок токена | с **16.11.2026, 09:00 МСК** до **23.11.2026, 00:00 МСК**. До начала срока API отвечает 401 |

**На стенде** `HACK_API_URL` и `HACK_TEAM_TOKEN` уже лежат в env вашего контейнера: берите их оттуда,
токен в код и в репозиторий не кладите.

Что умеет API (подробности и схемы ответов — в документации):

- `GET /health` — жив ли сервис, без токена;
- `GET /case/{1..4}/getData?dataset_code=<код>` — данные кейса. На dev вместе с данными приходит
  эталон (`reference`), по нему можно проверять своё решение. Коды наборов — в разделе «Наборы данных»;
- `POST /case/{1..4}/validate` — проверка формата вашего ответа на dev-наборе этого кейса. Набор
  определяется по токену, код передавать не нужно. Ответ — `{"valid": true|false, "errors": [...]}`.

`getData` каждый раз отдаёт один и тот же набор целиком. Загрузите его один раз и держите в памяти,
не запрашивайте заново на каждую запись.

Пример на Python, только стандартная библиотека:

```python
import json
import os
import urllib.error
import urllib.parse
import urllib.request

API = os.environ["HACK_API_URL"].rstrip("/")
TOKEN = os.environ["HACK_TEAM_TOKEN"]
DATASET_CODE = "<код dev-набора кейса 1 из раздела «Наборы данных»>"


def get_json(path, token=None):
    headers = {"Authorization": "Bearer " + token} if token else {}
    req = urllib.request.Request(API + path, headers=headers)
    with urllib.request.urlopen(req, timeout=120) as r:
        return json.load(r)


print(get_json("/health"))  # {'status': 'ok', 'datasets_loaded': ...}

try:
    data = get_json("/case/1/getData?dataset_code=" + urllib.parse.quote(DATASET_CODE), TOKEN)
    print(data["dataset"]["meta"]["dataset_id"], "эталон есть:", data["reference"] is not None)
except urllib.error.HTTPError as e:
    err = json.loads(e.read() or b"{}")
    print("HTTP", e.code, err.get("code"), err.get("message"))  # токен не печатаем
```

**С ноутбука** — из папки набора:

```
export HACK_API_URL=https://hack-api.be-healthy.tech
export HACK_TEAM_TOKEN="$(cat api.token)"
curl -s -o /dev/null -w '%{http_code}\n' "$HACK_API_URL/health"   # 200 — сервис отвечает
```

В Windows PowerShell: `$env:HACK_API_URL = "https://hack-api.be-healthy.tech"` и
`$env:HACK_TEAM_TOKEN = (Get-Content api.token -Raw).Trim()`.

Ошибки (тело ответа — `{"code": ..., "message": ..., "request_id": ...}`):

- **401** — токен не передан, неверный или вне срока действия (в том числе до 16.11.2026, 09:00 МСК);
- **403** «Нет доступа к набору» — этого кода нет в списке вашего токена: опечатка, чужой этап или
  такого набора нет вовсе (на все три случая ответ одинаковый);
- **404** «Набор не найден» — код ваш, но он от другого кейса: проверьте номер кейса в пути;
- **400** — нет `dataset_code` или тело запроса не JSON;
- **409** у `validate` — токен не закрепляет dev-набор этого кейса: напишите организаторам;
- **501** у `validate` кейса 2 — верный по формату ответ кейса 2 сервис пока до конца проверить
  не может (нужен симулятор номера). Ошибки формата он при этом показывает как обычно;
- **5xx** — сбой сервиса, повторите через несколько секунд.

## Наборы данных и dataset_code

Данные кейса берутся запросом `GET /case/N/getData?dataset_code=<код>`, где код — это `dataset_id` набора.
Наборы данных выдаёт только API: в архиве и в репозитории их нет. Вашему токену доступны dev-наборы,
по одному на кейс. Вам нужен код того кейса, который выбрала команда:

| Кейс | dataset_code (dev) |
|---|---|
| 1 | `case1-dev-v1` |
| 2 | `case2-dev-v1` |
| 3 | `case3-dev-v1` |
| 4 | `case4-dev-v2` |

- На dev вместе с данными приходит эталон (`reference`): по нему можно проверять своё решение.
- `validate` знает ваш dev-набор по токену, код ему передавать не нужно.
- Коды онлайн- и финальных наборов вам не выдаются: во время проверки код и токен придут в ваше
  решение от стенда в запросе `POST /run` (см. «Онлайн-проверка 20.11»).
- Наборы неизменны: при новой версии набора меняется его код. Если `getData` вдруг отвечает 403
  на код из этой таблицы, сверьтесь с последней версией README у организаторов.

## Нейросеть

| Что | Значение |
|---|---|
| Адрес | переменная `LLM_BASE_URL` (`https://bifrost.be-healthy.tech/v1`), совместим с OpenAI: подходит OpenAI SDK или любой HTTP-клиент |
| Ключ | переменная `LLM_API_KEY`, заголовок `Authorization: Bearer <ключ>`, ключ начинается с `sk-bf-` |
| Модель | переменная `LLM_MODEL` (сейчас `gpt-6-luna`), других моделей нет |
| Лимиты | 30 запросов в минуту и 300 тысяч токенов в сутки (вопрос + ответ) на всю команду |
| Срок | ключ работает до **23.11.2026, 12:00 МСК** |

**На стенде** `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL` уже лежат в env вашего контейнера. Берите их
только оттуда: ключ в коде и в репозитории не храните, имя модели в код не вписывайте. Если организаторы
сменят модель, они поменяют `LLM_MODEL` в env, и ваш код подхватит её без правок.
Пакет `openai` добавьте в `requirements.txt`.

```python
import os

from openai import OpenAI

client = OpenAI(
    base_url=os.environ["LLM_BASE_URL"],
    api_key=os.environ["LLM_API_KEY"],
    max_retries=0,  # повторы делайте сами, с паузой: каждый повтор SDK тоже идёт в лимит
)

resp = client.chat.completions.create(
    model=os.environ["LLM_MODEL"],
    messages=[{"role": "user", "content": "Привет! Ответь одним предложением."}],
    max_tokens=1100,  # ответ ~100 токенов + запас 1000 на скрытые рассуждения модели
)
print(resp.choices[0].finish_reason)  # "length" — ответ обрезан, поднимите max_tokens
print(resp.choices[0].message.content)
print(resp.usage)  # сколько токенов ушло
```

**Как не упереться в лимит токенов:**

- **Модель рассуждает перед ответом.** На каждый вызов уходит ещё около 400–500 скрытых токенов: в тексте
  ответа их нет, но они входят в `completion_tokens` и в суточный лимит. Поэтому `max_tokens` ставьте
  с запасом — **не меньше 1000 сверх ожидаемой длины ответа**. Иначе ответ обрежется
  (`finish_reason == "length"`), и JSON из него не разберётся. Проверяйте `finish_reason`.
- **Экономьте токены с первого дня.** Лимит — 300 тысяч токенов в сутки на всю команду, и он общий
  на разработку, ваши проверки и онлайн-показ. Не прогоняйте весь набор без нужды, отлаживайтесь на части данных.
- **Группируйте вопросы:** несколько вопросов — в один вызов. Решение «один вопрос — один вызов»
  на онлайн-наборе кейса 1 (1000 вопросов) съест в несколько раз больше суточного лимита.
- **Суточный лимит один на разработку и на проверку.** 19–20.11 не тратьте его подчистую: на онлайн-проверке
  ваш бэкенд получит 429 и не посчитает ответ. То же перед финалом 22.11.
- **429 — это лимит.** Ждите и повторяйте с паузой (5, 10, 20 секунд), не шлите запросы в цикле без задержки.

**С ноутбука** — из папки набора:

```
export LLM_BASE_URL=https://bifrost.be-healthy.tech/v1
export LLM_MODEL=gpt-6-luna
export LLM_API_KEY="$(cat llm.key)"
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $LLM_API_KEY" "$LLM_BASE_URL/models"   # 200 — ключ работает
```

В Windows PowerShell: `$env:LLM_BASE_URL = "https://bifrost.be-healthy.tech/v1"`, `$env:LLM_MODEL = "gpt-6-luna"` и
`$env:LLM_API_KEY = (Get-Content llm.key -Raw).Trim()`.

В ответе `/models` модель может называться с префиксом провайдера, например `openai/gpt-6-luna`.
В запросах пишите ровно значение `LLM_MODEL`.

Ошибки:

- **429** — лимит: больше 30 запросов в минуту или кончились токены за сутки. Подождите
  и повторите с паузой (например, 5, 10, 20 секунд), не шлите запросы в цикле без задержки.
  Суточный лимит сбрасывается раз в сутки, не обязательно в полночь;
- **401** — ключ не передан или неверный: проверьте `LLM_API_KEY` (без пробелов и переносов строки);
- **403** — срок ключа вышел, ключ отключили или модель не разрешена;
- **400** — неверный запрос, например другая модель. Подробности в поле `error.message` ответа;
- **5xx** — сбой сервиса, повторите через несколько секунд.

Ключ не печатайте в логах (никаких `print(os.environ)`), не кладите во фронтенд и мобильное приложение:
вызывайте нейросеть только со своего бэкенда. Если ключ утёк или вы в этом сомневаетесь, сразу напишите
организаторам: ключ отключат и выдадут новый.

## Онлайн-проверка 20.11

Проверку запускает сам стенд, без участия команды: он вызывает ваш бэкенд, а бэкенд берёт данные,
считает ответ и **возвращает его стенду в ответе на этот же запрос**. Сдавать ответ в API хакатона
не нужно: стенд сохраняет его сам.

**Сроки.** 20.11.2026 в 12:00 МСК деплой закроется: проверяется та версия бэкенда, которая работает
на стенде в этот момент. Это должна быть версия из коммита, который вы сдали через форму онлайн-показа
до 20.11, 12:00. На время проверки публичный адрес https://team10.hack.be-healthy.tech закрыт
(отвечает 503 «идёт проверка»), ваш контейнер при этом работает как обычно.

### Что придёт

Стенд один раз, по кейсу, который выбрала команда, отправляет на ваш бэкенд внутри стенда,
на порт `PORT`:

```
POST /run
Authorization: Bearer <токен проверки>
Content-Type: application/json

{"case": 1, "dataset_code": "<код набора>"}
```

Токен проверки — не ваш `HACK_TEAM_TOKEN`: он действует только на время проверки и открывает только
наборы этого этапа. Код набора в README не публикуется, он приходит только в этом запросе.

### Что сделать и что вернуть

1. Взять данные: `GET {HACK_API_URL}/case/{case}/getData?dataset_code={dataset_code}` с тем же
   заголовком `Authorization`, что пришёл в `/run`. Один раз, весь набор целиком; эталона (`reference`)
   в нём нет.
2. Посчитать ответ кейса. Нейросеть — как обычно, через `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`.
3. Вернуть ответ **в теле ответа на `/run`**: HTTP `200`, `Content-Type: application/json`, JSON ровно
   в том формате, который принимает `POST /case/{case}/validate`. Сами в API ответ не отправляйте.

Правила:

- **45 минут на прогон.** Стенд ждёт ответа до 45 минут, потом закрывает соединение. Не успели — попытка
  засчитана как таймаут.
- **Одна попытка.** Ответ не 200, обрыв соединения или таймаут — попытка всё равно засчитана,
  второго вызова не будет.
- Стенд сохраняет тело ответа как есть (до 64 МБ) и формат не проверяет: проверьте его сами заранее.
- Токен, данные и URL с кодом набора не печатайте в логи. Некоторые HTTP-клиенты сами пишут URL
  запроса в лог на уровне INFO: проверьте свой.

### Перед проверкой

**Прогоните свой ответ через `validate`** своим токеном: тот же JSON, который возвращает ваш `/run`,
отправьте в `POST {HACK_API_URL}/case/{case}/validate` с `HACK_TEAM_TOKEN` (на ноутбуке — `api.token`).
Нужно `"valid": true`.

**Сервер должен держать запрос до 45 минут.** uvicorn по умолчанию так и делает. У gunicorn воркер
по умолчанию убивается через 30 секунд: запускайте его с `--timeout 3000`, например
`exec gunicorn main:app -k uvicorn.workers.UvicornWorker -b 0.0.0.0:"${PORT:-8000}" --timeout 3000`.

**Память контейнера — 512 МБ.** Данные online кейса 3 — около 19 МБ JSON, после разбора в Python это
сотни мегабайт. Читайте набор один раз и не держите несколько копий (сырой текст, разобранный JSON
и таблица одновременно). Проверьте у себя в Docker с тем же лимитом (переменные — из `export` выше):

```
docker run --rm --memory 512m -p 8000:8000 -v "$PWD":/app -w /app \
  -e PORT=8000 -e HACK_API_URL -e HACK_TEAM_TOKEN -e LLM_BASE_URL -e LLM_API_KEY -e LLM_MODEL \
  python:3.11-slim sh -c 'pip install -q -r requirements.txt && sh start.sh'
```

**Проверьте `/run` на ноутбуке** на dev-наборе: ваш токен работает с dev-кодами. Запустите сервер
(`sh start.sh` или командой выше) и в другом окне из папки набора выполните:

```
curl -s -o answer.json -w '%{http_code} %{time_total} с\n' -X POST http://127.0.0.1:8000/run \
  -H "Authorization: Bearer $(cat api.token)" -H 'Content-Type: application/json' \
  -d '{"case": 1, "dataset_code": "<dev-код кейса 1 из раздела «Наборы данных»>"}'
curl -s -X POST "$HACK_API_URL/case/1/validate" \
  -H "Authorization: Bearer $(cat api.token)" -H 'Content-Type: application/json' \
  --data-binary @answer.json
```

Первая команда должна напечатать `200`, вторая — ответ с `"valid": true`. То же можно сделать на стенде
через https://team10.hack.be-healthy.tech/run, пока адрес открыт.

Заготовка `POST /run` с комментариями есть в `sample-app/main.py`: пока в ней нет логики, она честно
отвечает 501.

**Финал 22.11** запускается так же. До 11:00 вы сдаёте коммит через форму финального показа. С 11:00
до 12:00 стенд разворачивает бэкенд из этого коммита и вызывает `POST /run` с кодом набора финала
и токеном финала: ответ до 64 МБ, не дольше 45 минут. После ответа бэкенд должен продолжать работать:
во время защиты к нему обращается ваш клиент.

## Лимиты

- Память 512 МБ (если мало — напишите организаторам), CPU 1 ядро, до 256 процессов.
- Архив с кодом до 50 МБ, в распакованном виде до 300 МБ. Не кладите в репозиторий данные, модели, venv.
- Деплой не чаще раза в минуту. Сборки всех команд идут по очереди, ожидание — до 40 минут.
- Сборка до 15 минут. Скачанные пакеты кешируются: повторная сборка с теми же пакетами идёт быстрее.

## Сроки

- Токен API (`api.token`, `HACK_TEAM_TOKEN`) работает с **16.11.2026, 09:00 МСК** до **23.11.2026, 00:00 МСК**.
- Ключ нейросети (`llm.key`, `LLM_API_KEY`) работает до **23.11.2026, 12:00 МСК**.
- **20.11.2026 в 12:00 МСК деплой закроется.** После этого `deploy`, `logs` и `restart` будут недоступны,
  ваш контейнер продолжит работать, `status` останется.
